## Goal
A pure C++ `Safety` module in `firmware/armini/lib/core/` that decides, every tick, whether the robot may run. It debounces the leak probe, reacts to the kill switch immediately, applies battery hysteresis, watches a heartbeat, **latches** once tripped and releases only on an explicit reset with no active cause. Its verdict feeds `StateMachine` (SAFE). Fully unit-tested on the host. Plus the ESP32 hardware watchdog armed in `main.cpp`.

### Behaviour
- `Verdict tick(const SafetyInputs&, uint32_t now_ms)`; inputs: `leak_raw` (bool), `kill_raw` (bool), `v_bat`, `heartbeat_ok` (bool, main loop alive), optional `ladder_v` (if ≥ 0, decode it and OR into leak/kill).
- Leak: must be continuously true for `cfg.leak_debounce_ms` (default 100 ms, `// VERIFY`) before tripping. A 50 ms splash does not trip.
- Kill: trips on the **first** tick it is seen. No debounce.
- Battery: trips when `v_bat < cfg.v_trip` for `cfg.batt_debounce_ms` (default 500 ms); clears only when `v_bat > cfg.v_reset` (hysteresis). A single bad ADC sample (one tick) does not trip.
- Heartbeat: `heartbeat_ok == false` for `cfg.heartbeat_timeout_ms` (default 500 ms) → trip.
- Latch: once tripped, `verdict.safe == false` and `verdict.reason` stays until `reset()` is called **and** no cause is currently active. `reset()` with an active cause returns false and changes nothing.
- `reason` is a small enum: `NONE, LEAK, KILL, BATTERY, HEARTBEAT`. If several trip in the same tick, priority KILL > LEAK > BATTERY > HEARTBEAT.
- No heap, no Arduino types, time passed in.

2. kill one tick → trip immediately, reason KILL
3. kill + leak same tick → reason KILL
4. battery 9.8 V one tick → no trip; 600 ms → trip; rises to 10.2 V → still tripped (latch); reset at 10.2 V → refused; reset at 10.6 V → accepted
5. heartbeat false 400 ms → ok; 500 ms → trip
