# T11 · `esc` env: inverted output for an NPN level shifter · C006 / C025

**Branch** `dev` (daytime, small)
**Budget** 30 minutes

## Goal
Drive the thruster ESC signal through an S8050 NPN (open collector), because the ESC input idles at 5 V (C006). The NPN inverts, so the firmware must invert too.

## Context (C006, 23.10)
- Jesverty 9.00 V, ESC idle 0.009 A. Yellow (signal) → black: **4.983 V** open, **3.58 V** with 10 kΩ to black → internal pull-up ≈ 3.9 kΩ to 5 V. White → black 0.0002 V = signal ground.
- So yellow must never touch GPIO1/2 directly (ESP32-S3 is 3.3 V only).
- Bench circuit, per channel: GPIO1 → **1 kΩ** → S8050 base; **10 kΩ** base → GND (transistor off while the pin floats at boot); emitter → GND; collector → yellow. White → GND. Jesverty − ↔ DevKit GND (common ground). S8050 TO-92: E-B-C, flat face toward you, legs down.
- GPIO HIGH → transistor ON → yellow LOW. So the pulse on the pin must be LOW for `us` and HIGH for the rest of the 20 ms frame.

## Change (`firmware/bench/src/esc/main.cpp`)
- `const bool kEscInvert = true;  // SOURCE: C006 (ESC input pulled up to 5 V, driven through S8050 NPN)`.
- In `writeUs()`: when inverted, write `full − dutyFromUs(us)` (works on both Arduino core 2.x and 3.x, no GPIO-matrix call needed). `full = (1 << kEscBits)`, so 0 µs → pin always HIGH → yellow always LOW, and a 1500 µs pulse comes out right at the collector.
- Banner line: `# ESC output INVERTED (NPN level shifter, C006)`.
- PROTOCOL.md: replace step 1's "≤ 3.6 V → connect directly" branch with the measured result and the NPN wiring above; note the boot state (pin floats → base pull-down → transistor off → yellow held HIGH by the ESC = no pulses = ESC does not arm).
- PINOUT.md ESC rows: "via S8050 NPN, inverted (C006); rev B: JP1/JP2 → B + 74AHCT125".

## Tests (host)
