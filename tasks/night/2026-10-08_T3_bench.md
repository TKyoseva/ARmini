# T3 · Bench sketches for every module (DevKit-Lipo) + serial logger

**Branch:** `night/bench` → PR to `dev`
**Budget:** ~3 h agent time, or 3 failed attempts at one step.
**Independent of T1/T2.**

## Goal
In the morning Teddy can plug one module at a time into the DevKit-Lipo and run a known-good test sketch that prints CSV at 10 Hz, accepts a few serial commands, ramps slowly, has a soft power limit and a dead-man timeout. Each sketch has a one-page protocol: wiring, what to measure before power, expected numbers, pass criterion, what to photograph. A Python logger saves the CSV under the loop id for the tracker.

## Context
Read: `firmware/mega/bench/bench_v1.ino` (the Mega version: pot → BTS7960 with PWM_MAX 150, servo 20–160°, CSV 10 Hz — keep the same spirit), `hardware/breadboard/*.png` (the three breadboard sheets; sheet 2b is the DevKit-Lipo), `hardware/wiring/PINOUT.md`, `pcb/carrier-revA/SPEC.md`, `docs/bom/bom.csv` (module names and specs), `firmware/xiao/platformio.ini` (library names already chosen: Adafruit MLX90640, PWM Servo Driver, BNO055; SCServo from Waveshare).

Olimex ESP32-S3-DevKit-Lipo facts (manual p7, already in the repo image `Olimex_DevKit-Lipo_pinout_manual-p7.png`): used on board: GPIO5 = PWR_SENS, GPIO6 = BAT_SENS, GPIO38 = LED (active low), GPIO0 = button — **do not use these for modules**. 3V3 output max 600 mA. On-board LiPo connector is 1S only, never the 3S pack.

Pins: take them from the DevKit-Lipo breadboard sheet (2b). Put every pin in **one** header `include/pins_devkit.h`, each line with `// SOURCE: breadboard 2b` or `// VERIFY` if the sheet is ambiguous (e.g. which of a pair is SDA/SCL: pick one, mark VERIFY, list it in the README). Also add a "DevKit-Lipo" table to `hardware/wiring/PINOUT.md` from that header.

### Common behaviour (all sketches)
- CSV header once, rows at 10 Hz (MLX: 4 Hz), `t_ms` first column, no units in values, units in the header name (`is_r_mV`).
- CLI over Serial 115200: `?` help, `0` stop everything, module commands as above. Unknown command → `ERR <cmd>`.
- **Dead-man:** any actuator sketch stops outputs if no command arrived for 2 s (configurable). Print `DEADMAN` once.
- **Ramp:** actuator commands never jump; rate limit in the `Ramp` helper.
- **Soft limit:** actuator sketches start with the limit at 60 % and refuse `s 1.0` until `limit 1.0` is sent explicitly (printed as a warning).
- No WiFi, no secrets, nothing stored.

### PROTOCOL.md (each module, ≤ 1 page)
1. Wiring table pin → pin (from `pins_devkit.h`), wire colours.
2. **Before power:** continuity / short checks with the multimeter and expected readings (Ω).
3. **First power:** source (bench supply, current limit value), what to watch.
4. Steps with the CLI commands and the expected CSV numbers, with tolerance where known (e.g. ST3215 reports position within ±2° of command). Where you do not know the expected number, write `expected: record` — never invent.
5. Pass criterion, 1 line.
6. Photos: which (meter display, wiring, screen) and the file name pattern `C###_NN.jpg` in the card folder (see media/LINKS.md).
